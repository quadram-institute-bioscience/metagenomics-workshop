When extracting DNA from samples, if we want to focus on the microbiome we need to get 
a sample that has as limited contamination from unwanted organisms.

A typical example is the analysis of the gut microbiome: cells from the human host are usually
found in the samples (but typically negligible), while for other body sites (e.g skin) the amount
of human cells might be vastly superior to the microbiota cells.

In our workshop we won't focus on how to remove host cells from the samples (but methods [exists](https://www.nature.com/articles/s41592-023-02025-4),
and might even introduce further [biases](https://pmc.ncbi.nlm.nih.gov/articles/PMC10917613/))

## Removing host reads

There are different approaches, often based on mapping against a reference genome (i.e. the reads mapping are removed).
In general for processes like this we should consider:

1. Some regions are conserved across genomes, we might remove reads that are actually part of the microbiome (e.g. integrated retroviruses)
2. Sensitivity and specificity are traded-off
3. Choosing the right reference and eventually masking (removing) low-complexity regions or regions similar to bacterial 

So why dont' we simply leave the host reads?

1. The amount of host reads varies across samples, and this would make analyses more complicated trying to compare abundances
2. Several methods might classify  host reads as bacterial, inducing [to major errors](https://journals.asm.org/doi/10.1128/mbio.01607-23) especially in low-biomass samples

There is a host that is special: *Homo sapiens*. In our case we usually want to be more stringent in removing host reads (even at the risk of removing microbiome reads), to avoid patients data being identifiable. The genome is the most private biological property of an organism after all.


## Using Deacon

[Deacon](https://github.com/bede/deacon) is a fast host-depletion tool that does **not** align reads to a reference. Instead it builds an index of **minimizers** (a compact subset of the *k*-mers) from the reference genome, and removes a read when it shares enough minimizers with that index. This makes it very fast and memory-efficient compared to alignment-based tools.

:bulb: Deacon is available from Bioconda: `conda install -c bioconda deacon`. Pre-built indexes (e.g. `panhuman`) are also published for human host removal.

The workflow has three steps: **1)** build an index from the reference, **2)** mask it to avoid removing genuine microbiome reads, and **3)** filter the reads.

### Downloading the reference

You can use NCBI's `datasets` tool to download the `GCA_036785865.1` coffee reference 
[as described here]({{ site.baseurl }}/{% link modules/Extras/_posts/2001-01-01-ncbi-datasets.md %}).

### 1. Build the index

```bash
deacon index build coffee.fa.gz > coffee.idx
```

* The input (`coffee.fa.gz`) is the reference FASTA (plain or gzipped); use `-` to read from stdin.
* `-k` sets the *k*-mer length (default 31) and `-w` the minimizer window (default 15); the defaults are a good starting point.
* `-t` sets the number of threads.

### 2. Mask the index

As noted above, some regions of the host genome are similar to bacterial sequences. If we keep them in the index, we risk removing real microbiome reads. We can **subtract** the minimizers that the host shares with bacterial references, producing a *masked* index.

We don't need to assemble our own bacterial set: Deacon's own pre-built indexes are masked against **FDA-ARGOS 988**, a curated collection of 988 bacterial genomes published on [Zenodo](https://zenodo.org/records/15424142) for exactly this purpose. We download it and subtract it from the raw index:

:bulb: For the training, this file has already been downloaded for you — use the pre-downloaded copy (path provided during the session) instead of downloading the ~1.2 GB file yourself.

```bash
# Download the masking set (~1.2 GB; it is zstd-compressed, so we recompress to gzip)
curl -fSL 'https://zenodo.org/records/15424142/files/argos988.fa.zst?download=1' \
  | zstd -d | gzip > argos988.fa.gz

# Subtract the shared minimizers to produce the masked index
deacon index diff coffee.idx argos988.fa.gz > coffee.masked.idx
```

* `deacon index diff A.idx B` removes from `A` every minimizer also found in `B` (another index or a FASTA/FASTQ file).
* For a human host you can skip these two steps entirely and fetch a ready-masked index with `deacon index fetch panhuman-1`; the manual masking matters only for a custom host like coffee.
* Low-complexity sequence can also be ignored at filtering time with the `-c/--complexity-threshold` option (see below), so this masking step is optional but recommended when the host is phylogenetically close to members of the microbiome.

### 3. Clean the reads

To remove host reads we run `deacon filter` with the `-d/--deplete` flag (otherwise Deacon would *keep* the matching reads). For paired-end data we pass both FASTQ files and write two cleaned outputs:

```bash
INDEX=coffee.masked.idx
OUTDIR=cleaned-reads
mkdir -p $OUTDIR

deacon filter --deplete --threads 8 \
  --check-pairs \
  $INDEX $R1 $R2 \
  -o $OUTDIR/${BASE}_1.fastq.gz \
  -O $OUTDIR/${BASE}_2.fastq.gz \
  --summary $OUTDIR/${BASE}.deacon.json
```

* `--deplete` removes the reads matching the host index (host depletion).
* `$R1` and `$R2` are the input reads; `-o` and `-O` are the two cleaned outputs.
* `--check-pairs` validates that the two files stay in sync.
* `--summary` writes a JSON file with the statistics.
* `-c 0.1` (optional) ignores low-complexity matches.

### Summary statistics

The JSON summary reports how many reads (and bases) were removed. For paired data each pair counts as **two** sequences, so a pair where both mates are host contributes 2 to `seqs_removed`.
